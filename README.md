# 城市社区儿童疫苗补种提醒与异常反应随访平台

Vue 3 + Spring Boot 3 + MySQL 8 实现的 0→1 演示工程，覆盖「儿童档案 → 智能接种/补种计划 → 预约 → 到诊核验 → 接种留观 → 异常反应随访/上报 → 家长咨询」全闭环，库存、预约、接种、随访统一汇聚为儿童维度健康档案。

---

## 原始需求

建设城市社区儿童疫苗补种提醒与异常反应随访平台，可采用 Vue 3、Spring Boot 和 MySQL。家长建立儿童档案后，平台根据出生日期、既往接种、迁入记录、禁忌症、过敏史和疫苗库存生成接种计划。预约时，系统根据门诊容量、疫苗批号、冷链状态、医生排班和儿童健康状态判断可约时段。到诊后，护士核验儿童身份、疫苗批号、知情同意、近期发热和禁忌症；接种完成后，留观时间、现场反应和家长确认进入记录。若儿童漏种、迁入记录不全、疫苗库存不足、家长临时取消或接种后发热皮疹，平台需要把状态推给预防接种医生、护士和随访人员。补种提醒要结合最短间隔、年龄上限和库存到货。异常反应随访会关联接种批号、症状、就医记录和最终判断，帮助门诊处理家长咨询和上报材料。平台还要支持社区医生按儿童、疫苗和批号追踪异常，便于处理家长咨询和区级上报。家长咨询记录会进入儿童下次接种前提醒。平台还要把库存、预约、接种和随访连成儿童维度的健康档案，门诊可以解释某次补种为何延后、为何换苗或为何需要医生复核。

## 一、快速启动（Docker 一键部署）

前置：已安装 Docker 与 Docker Compose 插件。

```bash
cd /workspace
cp .env.example .env          # 可按需修改端口/密码/JWT 密钥
docker compose up -d --build  # 构建并启动 db(mysql8.4) + app(spring boot) + web(nginx+vue3)
```

- 仅 **web（前端 nginx）** 发布宿主机端口：`${CC_PUBLISH_PORT}:8080`；
- MySQL **不发布宿主端口**，只在 compose 内网通过服务名 `db:3306` 被 app 访问；
- 前端 nginx 把 `/api/` 反向代理到 `app:8080`，无跨域问题；
- 首次启动 app 会自动建表并写入演示数据（幂等，已初始化则跳过）。

查看实际映射端口与健康状态：

```bash
docker compose port web 8080
docker compose ps
curl -s http://localhost:${CC_PUBLISH_PORT}/api/health
# {"code":0,"message":"success","data":{"status":"UP","db":"UP","app":"vaccine-platform"}}
```

浏览器访问：`http://<宿主IP>:<CC_PUBLISH_PORT>/`（验证环境使用 `http://host.docker.internal:<docker compose port 输出的端口>/`）。

停止与清理：

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 同时删除数据库卷（恢复全新演示数据）
```

- **王二宝**（parent1，2026-08-01 出生）：月龄小，可看到「最短间隔/起始月龄未满」状态。
- **吴朵朵**（parent2，2024-03-10 出生）：本地接种史完整；有 1 例 MMR（批号 `MMR-202509`）**发热皮疹 AEFI，随访中且下次随访今天到期**；近期发热申报会阻断当日预约；水痘减毒活疫苗有禁忌；一条咨询已标记为**下次接种前提醒**。
- **库存**：`IPV-202509`/`MMR-202509` 缺货、`VAR-202507` **冷链中断封存**、`HEPB-202408` 已过期——可约时段会自动排除并解释；管理员入库后相关计划**自动从「等待库存」转为可预约**。
- **容量/排班**：未来 10 个工作日自动生成 4 个时段；每日 `14:00-14:30` 刻意无医生排班，用于演示不可约原因。

## 四、建议的验证业务流（浏览器）

1. `parent1` 登录 → 王小明计划中可见漏种、酵母过敏待复核、等待库存/换苗等状态及解释；对「可预约/漏种」剂次点预约，时段表逐行展示容量余号、值班医生、可发批号/效期/冷链与不可约原因。
2. `doctor` 登录 → 「医生复核」页同意王小明乙肝剂次 → 家长即可预约。
3. `nurse` 登录 → 今日门诊「到诊签到」→ 到诊核验页完成**身份/批号/知情同意/近期发热/禁忌**五项核验（页面顶部同时展示家长咨询的接种前提醒与健康申报）→ 接种扣库存 → 30 分钟留观 → 记录现场反应、家长确认后归档；勾选「发现异常反应」会自动建 AEFI 并推送医生/护士/随访人员。
4. `followup` 登录 → 对吴朵朵 MMR 个案增加随访（体温/症状/转归/下次随访日期）；`doctor` 可登记就医记录、做最终判断、生成区级上报；顶部铃铛支持按儿童/疫苗/批号筛选追踪。
5. `admin` 登录 → 新批号入库（如补充 IPV）→ 等待库存的计划自动开放可约；可模拟冷链封存、库存调整，系统即时重算。
6. 家长「我的预约」中临时取消 → 医生/护士/随访人员铃铛收到推送；家长咨询被回复并勾选「接种前提醒」后，护士到诊核验页自动带出。
7. **迁入接种本核验闭环**：parent1 在王小明「档案与健康申报」上传接种本（图片或文本）→ 自动识别出待核验/模糊记录 → 计划中相应剂次显示「迁入待核验」、暂不可约 → `doctor`/`nurse` 在「接种本核验队列」查看原件、纠正字段后确认（跳过该剂）或驳回（追加补种）→ 计划重算、后续时段重新开放、护士到诊时可见每剂跳过/追加原因。

## 五、关键设计如何对应需求

- **计划生成**（`PlanService`）：出生日期 + 程序模板（建议/最早/年龄上限月龄、剂间最短间隔天数）+ 既往接种（本门诊 `LOCAL` 直接计入，迁入 `MIGRATED` 必须核验后计入；同疫苗组按序贯匹配，支持 IPV/bOPV、MR/MMR 换苗）+ 活动期禁忌症 + 过敏史成分匹配（疫苗 `components` 关键字）+ 批号库存/冷链/效期，产出 `DUE/OVERDUE/WAIT_INTERVAL/WAIT_STOCK/CONTRA/REVIEW/EXPIRED/DONE` 状态与可解释备注。
- **可约时段**（`AppointmentService`）：门诊容量（乐观锁防超约）× 医生排班 × 可发放批号 × 最短间隔/年龄上限 × 儿童近期健康申报联合判定，不可约时逐行给出原因。
- **状态推送**（`NotificationService`）：漏种、迁入不全、库存不足、家长取消、接种后发热皮疹、随访到期、咨询待回复、接种前提醒等按角色广播或定向推送，前端铃铛 15 秒轮询、未读去重。
- **补种提醒与到货联动**：每日 07:10 定时任务重算全部计划（爽约置漏种、随访到期提醒）；管理员入库/冷链恢复会立即触发全量重算，满足「最短间隔 + 年龄上限 + 库存到货」后自动开放。
- **AEFI 全链路**（`AefiService`/`FollowUpService`）：关联接种记录与批号、症状/发病日期、就医医院与记录、多次随访转归、最终判断（一般反应/异常反应/偶合症/心因性反应/不能排除/无因果关系）、区级上报；支持按儿童、疫苗代码、批号三维检索。
- **儿童维度健康档案**（`ChildService.healthRecord`）：计划、迁入/既往接种、接种记录（含换苗与暂缓原因）、AEFI、家长咨询合并为时间线，可解释「为何补种延后、为何换苗、为何需医生复核」。
- **迁入儿童接种史核验**（`MigrationService`）：家长在「档案与健康申报」上传外地接种本（图片模拟 OCR / `.txt` 文本本），平台把疫苗名称、剂次、日期、批号识别为待核验记录，置信度低或疫苗/批号无法识别的自动进入**人工提醒队列**；同疫苗组存在待核验记录时，相关剂次置为 `WAIT_VERIFY`（迁入待核验），**不可预约，防止重复接种或越剂漏种**。医生/护士在「接种本核验队列」可预览原件、纠正疫苗/剂次/日期/批号后**确认采信（该剂跳过）**或**驳回（该剂转为追加补种）**；确认后系统重算到具体剂次并**重新开放后续可约时段**，每剂生成「为何跳过/追加/延后/换苗」的剂次调整说明，护士到诊核验页直接展示。文本本每行格式：`疫苗代码,剂次,接种日期,批号,原单位,置信度`（页面可下载模板）。

## 六、技术结构

```
backend/   Spring Boot 3.3 (Java 17)、Spring Security + JWT、Spring Data JPA、MySQL、Actuator
           多阶段 Dockerfile（maven 构建 → jre 运行；非 root 用户 vax；HEALTHCHECK）
frontend/  Vue 3.5 + Vue Router 4 + Vite 5（无额外 UI 库，原生 CSS）
           多阶段 Dockerfile（node 构建 → nginxinc/nginx-unprivileged 非根运行；HEALTHCHECK）
docker-compose.yml   db(mysql:8.4, 内网) + app(8080, 仅 expose) + web(发布 ${CC_PUBLISH_PORT}:8080)
```

验证方式＝在宿主机执行 `docker compose up -d --build`，以容器健康检查为 UP、且上述关键业务流可在浏览器走通为准。
